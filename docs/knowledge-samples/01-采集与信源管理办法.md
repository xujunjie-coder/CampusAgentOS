# 政务数据采集与信源管理办法

## 一、适用范围

本办法适用于数据瞭望系统（GovCheckDataAgentOS）接入的全部公开信源，包括新闻门户 RSS、
政务公开网站、公开数据接口等。系统内所有采集任务、关键词、入库字段均按本办法执行。

## 二、信源准入

1. 信源必须可公开访问，不得绕过登录、验证码、付费墙或 robots 协议限制。
2. 每个信源需登记：名称、类型（RSS / API / 页面）、入口地址、更新频率、责任成员。
3. 系统内置信源不少于 3 个，当前默认启用：百度资讯搜索、Google 新闻 RSS、人民网要闻。
4. 新增信源须先在「信源管理」页登记并通过一次试采集，采集到不少于 5 条有效条目后才可置为启用。

## 三、关键词与采集频率

1. 关键词按业务主题配置，单次任务关键词不超过 8 个，避免结果集互相污染。
2. 同一信源的最小采集间隔为 30 分钟；高频轮询会给对方站点造成压力，属违规使用。
3. 采集任务失败连续 3 次，应自动降级为「暂停」，由管理员排查后再恢复。

## 四、入库字段规范

采集条目入库时必须包含以下字段：

- `title`：标题，去除首尾空白，长度不超过 200 字；
- `url`：原始链接，必须为完整可访问地址，禁止站内相对路径；
- `source_name`：信源名称，与信源表保持一致；
- `summary`：摘要，保留原文前 400 字以内；
- `published_at`：发布时间，无法解析时留空，不得用采集时间顶替；
- `collected_at`：采集时间，由系统写入，不接受外部传入。

## 五、去重与清洗

1. 以 `url` 为唯一键去重，同一链接重复出现时保留最早一条。
2. 标题与已入库条目相似度极高（正文前 80 字完全一致）时，视为转载，标记为副本不入库。
3. 正文清洗需剔除导航、版权声明、推荐位等噪声，保留段落结构。

## 六、数据安全

1. 采集内容只用于内部分析与预警，不得对外转售或再分发。
2. 涉及个人隐私的内容（身份证号、手机号、住址）入库前必须脱敏。
3. 采集日志保留 30 天，超期由定时任务自动清理。
