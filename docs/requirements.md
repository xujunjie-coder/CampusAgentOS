# 功能性需求分析

本文覆盖团队任务书中成员 B 负责的 AI 核心模块。用户、角色和菜单由现有模块提供，数仓作为采集数据的下游。大屏、定时通知、人脸登录、3D 数字人、音乐、PDF 导出和系统管理由团队其他模块对接。

| 编号 | 功能 | 验收标准 |
| --- | --- | --- |
| B-01 | 模型引擎与 AHLLMProxy | 后台可测试和设置 OpenAI 兼容的默认对话模型。数字员工可绑定启用的对话模型。对话使用 Agentica 流式输出，采集和舆情使用同一套模型选择逻辑。 |
| B-02 | 数字员工与工具链路 | 后台可配置数字员工提示词、模型、知识文档及工具。启用数仓检索后可按关键词查已入库新闻，启用 MCP 搜索后可查询互联网资料。 |
| B-03 | 信源与自动化采集 | 信源管理至少提供百度新闻、中新网即时新闻 RSS、Google 新闻 RSS。管理员输入关键词并选择多个信源后，系统逐源抓取、由 Agentica 提取候选条目、校验链接来源、去重入库。模型不可用时保留 RSS 或 HTML 规则回退。 |
| B-04 | 知识仓库 RAG | 管理员可粘贴正文或导入 UTF-8 TXT、Markdown。正文切片后由启用的嵌入模型或本地词项向量生成器生成向量。对话只检索当前助理关联的文档，按余弦相似度召回片段，回答应注明文档标题。 |
| B-05 | 多轮对话 | 同一账号可以新建和切换会话。刷新后可重开历史会话，原有消息归入默认会话。同一会话最近八轮上下文参与下一次回答。其他账号使用同一会话编号仍读不到该会话数据。 |
| B-06 | 智能舆情 | 采集结束后后台分析新闻标题和摘要，区分高风险、关注、常规、待重试。高风险和关注必须附原文证据，后台通过 WebSocket 更新结果，管理员可重试。模型筛查结果由人工复核。 |

# 非功能性需求分析

- 兼容性。保持单一入口、控制层／服务层／模型层与模板静态资源分层。沿用 SQLite，迁移可重复运行，支持旧消息。团队集成时还需按任务书单独验证 Torndao、Bootstrap、ECharts 和 MySQL 等全组约束。
- 权限与隐私。管理页和舆情连接使用登录与菜单权限，表单启用 CSRF 校验。会话按登录账号和会话编号隔离。数字员工绑定的知识文档视为该员工的共享资料。
- 安全性。网页正文、知识片段和 MCP 返回视为数据。采集校验模型输出链接是否出自页面，舆情校验引文是否出自标题或摘要。模型服务密钥由项目运行环境提供。
- 可靠性。采集逐源隔离故障。知识文档及向量在全部嵌入完成后一起写入。问答成功后成对保存，一次只接受同一账号同一会话的一轮进行中请求。模型失败时保存待重试状态。
- 性能。限制单次采集源数、知识文档大小、对话上下文长度与模型调用超时。风险分析在后台分批运行，页面连接最多每 3 秒检查一次变化。
- 可追溯性。区分智能体、RSS 和规则解析，保留来源和风险判断依据。本私人练手项目已获用户授权，项目依赖不受用户自定的许可证白名单限制。
