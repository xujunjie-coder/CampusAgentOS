# 行署校区三维地图

平台入口 `/campus-map`，侧栏“行署校区三维地图”进入，须登录。当前是本地 Three.js 模型的浅色地图展示，不是腾讯/高德在线地图，也未取得商业地图三维数据。

## 本次实现

- 原 GLB 的 42 栋建筑几何不变。按面法向区分屋顶和墙面材质，更新道路、水体、地面配色，增加光照与阴影；配色是示意，不用于推断真实绿化覆盖。
- 建筑名称采用原 manifest。候选节点显示“待核验建筑 XX”，已登记名称仍有 `?` 提示。建筑详情读取三组审查 JSON，提示清单与模型内部名称差异。
- 名称锚点来自每栋建筑模型包围盒顶部，自动智能避让；缩放、旋转和平移时同步重新投影。
- 建筑名称只在俯视视角显示，倾斜后自动隐藏；西门、南门名称与位置色点在所有视角保留，并优先放置校门名称。校门点位按原参考示意图与已有仿射配准计算，非实测，`landmarks.json` 保留参考像素和变换参数。点击“俯视全校”或指南针恢复建筑名称。
- 搜索和选择合并为一个可筛选下拉框，支持方向键、Enter、Escape以及点击选项定位。工具栏保留“俯视全校”和“全屏查看”，移除单独建筑下拉框、聚焦建筑、重置视角和名称设置。顶部文案为“本地图由学生绘制，非官方。”
- 搜索定位、名称点击、建筑点选、全校俯视、朝北、缩放、全屏；Shift/右键拖动平移，触屏双指缩放和平移。
- 沿用平台已有 Three.js r128 和 GLTFLoader，不依赖 CDN，不请求外部影像或位置权限。

用户参考截图为腾讯地图的华凤校区，只用于浅色楼块与标注风格参考。本页仍为行署校区，不把截图中的华凤建筑、道路或名称移植到行署。

## 证据与模型边界

审查文件按 1–14、15–28、29–42 分组，覆盖所有 42 栋；对应报告位于本目录，机读 JSON 位于 `app/static/maps/xingshu-campus/`。审查未完成腾讯逐栋 3D 图像对照，没有根据估计名称新增所谓真实立面。GLB 内部所有建筑均非实测；内部旧名与 manifest 不一致并不自动证明其中一方正确，因此保留原清单名并提示差异。

原始 manifest 的 WGS84 原点和 UTM EPSG:32648 局部坐标可用于后续配准。不能把局部米坐标直接当经纬度，也不能把 WGS84 数值直接用于要求 GCJ-02 的底图。正式叠加需完成坐标转换、控制点对齐与偏差核验。

真实细化应逐栋补充：能确定建筑身份和拍摄方向的当前照片/全景、轮廓控制点、层数/高度依据、屋顶结构、资料时间和许可。先解决名称身份冲突，再修改体量；新几何需保留证据、版本与包围盒校验，不以外观相似代替位置或身份核验。

若要接入真实卫星底图，可使用地图厂商正式 SDK；是否有该校区的详细三维数据必须实测覆盖，不能将移动端截图视作 Web SDK 的覆盖证明。高德官方示例区分[卫星图层和三维楼块](https://lbs.amap.com/demo/javascript-api-v2/example/layers/buildings)，以及[自定义三维数据](https://developer.amap.com/demo/list/jsapi-v2)。正式接入前需要项目可用的 SDK 凭据、域名配置与适用的数据使用权限。本版没有下载瓦片、提取腾讯模型、解密学校全景配置或接入收费服务。

## 验证

- `node tests/test_campus_map_labels.cjs`：名称优先级、避让、视口边界、全部/关闭模式、详情遮挡区与确定性。
- `venv/Scripts/python.exe -m pytest tests/pytest/test_campus_map.py tests/pytest/test_knowledge_retrieval.py -q`：地图鉴权、静态资源、GLB 原始哈希与 42 个建筑节点、42 条审查记录以及知识内容渲染回归。Windows 沙箱会阻断 asyncio socketpair 时须在允许本地回环的环境执行。
- 浏览器核对桌面和 390px 手机视窗、搜索定位、名称点击与冲突提示。正式腾讯/高德服务未接入，未作覆盖或计费验证。
