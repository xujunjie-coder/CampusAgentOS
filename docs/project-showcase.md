# 项目讲解与求职展示

## 一分钟介绍

CampusAgentOS 是面向校园服务和信息管理的 Python 全栈 AI 应用。前台提供流式对话、知识库问答、多智能体协作和三维校园地图；后台提供网页与 QQ 频道采集、知识文档管理、舆情初筛、统计大屏及权限管理。

主要工程工作是将数据接入、模型编排、长任务状态、人工复核和用户界面连成闭环。例如，QQ 检索先保存摘要，用户打开选中帖子后才读取全文、图片地址和评论；初筛需要提供原文证据，人工结论独立保存。项目使用 Tornado、Agentica、SQLite / MySQL、Playwright 和 Three.js 等技术。

介绍时根据自己实际承担的工作调整主语和范围，不将整个代码库的能力自动等同于个人独立完成。

## 技术决策与代码证据

### 1. 长任务不阻塞界面

采集任务在线程池执行，数据库保留运行状态和进度，前端轮询任务接口；对话使用 SSE 传输工具状态、子任务结果和回答片段。不同链路选择不同的反馈方式，并非所有操作都走同一种通信机制。

- 代码：[QQ 采集服务](../app/services/qq_channel_service.py)、[QQ 控制器](../app/controllers/qq_channel.py)、[对话控制器](../app/controllers/chat.py)。
- 可追问：停止信号何时检查？页面退出后任务怎么办？多进程如何共享任务状态和互斥锁？
- 当前取舍：进程内线程池与互斥适合本地单实例；分布式队列尚未实现。

### 2. 模型有工具，也有执行边界

主助手可分派独立研究任务。子任务使用只读查询白名单，不继承完整主会话；通过 ContextVar 维护各子任务独立的共享查询预算，限制并行批次中的实际查询次数，并设置超时和返回格式。界面呈现各任务状态与返回结果。

- 代码：[智能体服务](../app/services/agent_service.py)、[协作测试](../tests/pytest/test_chat_collaboration.py)。
- 可追问：为什么仅在提示词里写“最多查询三次”不够？并行调用如何共享预算而不影响其他子任务？异常退出如何恢复上下文？
- 当前取舍：框架轮数限制配合工具层预算；真实模型仍可能超时或输出不理想，模拟测试只验证控制逻辑。

### 3. RAG 从文档处理讲到回答引用

上传文档后按标题和段落切片，检索时结合中文词元 BM25 与向量相似度，向回答提供资料来源。未配置嵌入模型时采用本地词项向量，以支持基本运行。

- 代码：[检索服务](../app/services/intelligence_service.py)、[文档存储](../app/models/intelligence.py)、[知识管理入口](../app/controllers/intelligence.py)。
- 可追问：切片为何保留标题？关键词检索和语义检索各有什么不足？更换嵌入模型后已有索引如何处理？
- 当前取舍：向量保存在业务数据库中计算相似度，没有引入专用向量数据库；未提供大规模检索基准。

### 4. QQ 采集有范围和成本控制

通过 Playwright 操作频道内搜索并校验范围。以频道和帖子 ID 组织数据，先保存摘要，再按需读取单帖详情；图片保存 URL，评论/回复按父子关系展示，整帖审核集中处理。信源后台维护频道并控制是否出现在采集选项中。

- 代码：[采集](../app/services/qq_channel_service.py)、[存储与接入舆情](../app/models/qq_channel.py)、[信源](../app/models/source.py)、[前端](../app/static/js/qq-channel.js)。
- 可追问：虚拟列表如何累积结果？加载失败为何不能当作零条？为何不在搜索时展开所有评论？如何避免把头像和表情当正文图片？
- 当前取舍：依赖 DOM 结构和登录权限，搜索返回不代表全部历史；原图链接可能失效，未做永久归档或 OCR。

### 5. 模型初筛与人工认定分开

模型输出结构化分类和原文证据，代码检查证据是否为标题/摘要中的连续片段。校验失败保留为待重试，人工审核不被 AI 结果覆盖。高风险与关注用于线索优先级，不等于事实核实或违规认定。

- 代码：[风险初筛](../app/services/intelligence_service.py)、[频道 AI 分析与审核](../app/controllers/qq_channel.py)。
- 可追问：证据逐字匹配能防住什么、不能防住什么？如何处理误判？内容更新后旧结论怎样处理？
- 当前取舍：证据匹配能约束输出来源，不能证明来源真实，也不能保证分类正确。

### 6. 三维交互保留数据依据

地图通过 GLB 和 Three.js 展示楼块，结合射线拾取、屏幕标注、相机平移/聚焦和局部坐标测距。华凤白模由 OSM 轮廓生成，名称和分栋校正以元数据保留，并在重建脚本中应用。

- 代码：[地图交互](../app/static/js/campus-map.js)、[模型构建](../scripts/build_huafeng_campus_map.mjs)、[名称校正](../scripts/huafeng_name_corrections.mjs)。
- 可追问：三维点怎样投影为屏幕标签？如何避让？局部坐标与经纬度有何不同？
- 当前取舍：展示模型和截图示意位置，不承诺实测精度或室内导航。

## 五分钟演示顺序

1. 从知识仓库中选一份可公开资料，说明文档切片、检索和绑定助手的流程。
2. 发起有两个独立方向的问题，展示子任务状态与主助手汇总；提前准备模型不可用时的替代演示。
3. 在信源管理中展示 QQ 频道配置，在采集页选择频道并检索，说明日期和条数限制。
4. 打开一条有访问权限的帖子，展示正文、图片、嵌套回复和整帖审核。
5. 展示三维校园地图及统计明细，最后打开对应代码和回归测试解释一个设计取舍。

演示使用自己有权展示的资料。个人账号、登录资料及真实用户对话不作为公开截图素材。
