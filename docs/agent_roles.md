# 项目协作规则

> 本文件约定人类与AI代理（以下简称【代理】）在项目中的协作边界与工作方式。
>
> 标注的条款由代理依据现状拟定，需人类负责人确认后生效或执行。

## 1、发布决策权

1、现有代码由人类完成开发，后续代理需要在此基础上参考完成剩余开发任务。
2、开发所需要规则和发布需要以人类既定的规则为准，不能串改、创新、编造。
3、唯一发布决策人为人类负责人。代理不拥有以下权为：

- 不得自行决定发布、打Tag、合并到主干。
- 不得执行`git push`、`git commit`，除非人类明确指令，不得修改git配置。
- 不得执行强制推送、重置、删除分支等破坏性操作。
- 不得自行变化需求范围、技术选型与架构基线。
  4、涉及到敏感数据或venv目录文件，主动提示不上传。
  5、代理遇到需求不明、方案不分歧、操作具有破坏性风险时，必须先提问/出给选项，不得替人类做决定。

## 2、版本号规则

1、初始版本遵循GUN协议规范：v0.0.0
2、版本号记录在VERSION文件中（docs/VERSION）。
3、人类指明发布版本时，次版本号加1，即v0.x.0=x+1。
4、在完成功能模块的开发后，允许版本号管理，次版本号可以加1，即v0.x.0=x+1。
5、git提交版本与开发版本号保持一致，即本地为v0.1,线上版本为v0.1,本地与线上同步。

## 3、工作流范式

1、人类下达指令->代理阅读docs/*.*相关资料->列出执行计划（必要时提问确认）->人类确认->代理编码->自测（测试用例代码必须放置tests/*.*）->汇报变更结果->测试通过结果->人类决定提交与发布。
2、先学习后动手：识别到人类变更的行为和结果，需要自行学习并补充到自行的规则中。
3、遵循编码规范：严格按人类代码的编码风格、规范、命名风格完成编码。按分层归档代码程序，不要乱放程序文件到不相干目录。
