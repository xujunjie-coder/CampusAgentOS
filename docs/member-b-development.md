# 成员 B 开发与验收指南

## 开发提示词

> 先读取需求说明、目录框架与现有模块。按成员 B 的功能编号列出当前差距，并从对应页面和 API 验证实际行为。沿用 app.py、application.py、现有页面样式及 Repository 分层。只修改当前功能涉及的文件。优先复用已有模型服务、数据表与鉴权。对旧 SQLite 数据做幂等迁移。服务凭据从运行环境获取，禁止把真实凭据放进文档、测试或日志。外部调用使用模拟响应验证成功、超时和异常输出，再在部署环境联调。交付时列出可复现步骤、测试结果、仍需配置的外部服务及团队集成差距。

## 接入配置

- AHLLMProxy 使用 OpenAI 兼容地址。优先在「模型引擎」维护对话模型，按项目环境填写地址、模型 ID、密钥并设默认。没有启用默认项时，可使用环境变量 `AHLLM_PROXY_BASE_URL`、`AHLLM_PROXY_API_KEY`、`AHLLM_PROXY_MODEL_ID`，也兼容旧的 `BASE_URL`、`API_KEY`、`MODEL_ID`。地址应为代理提供的 API 基地址，例如以 `/v1` 结尾的地址。
- MCP 默认连接应用内置的 `/mcp/news`，通过 Google 新闻 RSS 按关键词查询公开新闻。内置服务只接受携带进程令牌的本机请求。在数字员工中勾选「MCP 网络搜索」即可启用。需要自带服务时，设置 `MCP_URL`、`MCP_SEARCH_TOOL` 以及可选的 `MCP_TOKEN`，工具应接收字符串参数 `query`。协议使用 [MCP 2025-11-25 Streamable HTTP](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)。
- 未启用嵌入模型时，知识仓库使用本地词项向量，支持中文单字、相邻双字和其他语言的词级匹配。启用远程嵌入模型后，系统使用第一个启用的嵌入模型。切换向量方式或模型后，重新导入文档并更新员工绑定。
- 运行项目使用团队批准的 Python 虚拟环境和依赖版本。从仓库根目录通过虚拟环境的 Python 运行 `app.py`。仅在本机使用时，将 `GOVCHECK_BIND_HOST` 设为 `127.0.0.1`。

## 联调验收

1. 打开 `/admin/models`，分别测试默认对话模型和启用的嵌入模型。
2. 打开 `/admin/knowledge` 上传含唯一词语的 UTF-8 文档，记下文档编号。在 `/admin/employees` 绑定文档，按需勾选「数仓检索」「MCP 网络搜索」。从前台选择该员工并提问，观察文档引用和工具调用。
3. 在 `/admin/sources` 检查百度新闻、中新网即时新闻 RSS 和 Google 新闻 RSS。进入 `/collect`，选择三条信源及关键词，检查逐源状态和重复采集去重。中新网是固定滚动订阅，规则回退按标题或摘要筛选关键词。两个 RSS 源均返回 XML，百度可能返回验证页。
4. 在前台创建会话 A，输入一条自定义信息后追问。创建会话 B，确认未带入 A 的历史，再从历史列表返回 A。使用另一个账号验证历史隔离。
5. 采集后打开 `/admin/sentiment`，检查 WebSocket 状态、风险等级和证据。使用「分析待处理条目 / 重试失败」补扫历史数据。未经人工复核的模型输出只作为风险线索。
6. 执行 `python -m unittest discover -s tests -p test_member_b.py`。测试使用内存 SQLite、模拟模型输出及本地 MCP 端点，无需真实服务密钥。

前台会话上下文从 SQLite 恢复，每轮创建独立的 Agent。员工级工作空间长期记忆不参与此路径，避免跨会话带入聊天内容。外部资料可进入模型提示，只有允许共享的数据才应绑定到对外可选的员工。
